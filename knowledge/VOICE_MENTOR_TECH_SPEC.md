# Техническая спецификация: Ferixdi AI Voice Mentor

## Цель
Отдельное веб-приложение для студентов, где наставник отвечает голосом, использует базу знаний Ferixdi AI и сохраняет контекст обучения в рамках разрешённой политики хранения данных.

## Рекомендуемая архитектура
- **Frontend:** отдельное веб-приложение (например, Next.js/React) с микрофоном, воспроизведением аудио, текстовым транскриптом и управлением сессией.
- **Backend:** серверные endpoints для аутентификации студента, проверки доступа, работы с OpenAI API и retrieval.
- **Voice:** выбрать поддерживаемый OpenAI realtime/audio workflow после проверки актуальной документации. Не жёстко зашивать устаревшие имена моделей.
- **Knowledge retrieval:** хранить документы курса отдельно от системного промпта; разбивать на фрагменты, снабжать метаданными (источник, раздел, урок, дата проверки) и искать релевантные фрагменты по вопросу.
- **Storage:** хранить прогресс/историю только при необходимости и с понятным уведомлением пользователю.
- **Observability:** журналировать ошибки, задержки и расход токенов без сохранения лишних чувствительных данных.

## Поток запроса
1. Студент проходит серверную аутентификацию.
2. Backend проверяет право доступа к наставнику.
3. Запрос/аудио направляется в поддерживаемый voice workflow.
4. Для предметного ответа извлекаются релевантные фрагменты курса.
5. Модель получает system prompt + вопрос + контекст источников.
6. Ответ возвращается голосом; при необходимости показывается транскрипт и ссылки на источники.
7. При недостатке материалов наставник признаёт пробел, а не выдумывает ответ.

## Безопасность
- OpenAI API key хранится только в серверных переменных окружения.
- Никогда не встраивать секреты в клиентский JavaScript, публичный GitHub или статический сайт.
- Публичный GitHub подходит для исходного кода и обезличенной документации, но не для закрытой базы курса, приватных ключей и данных студентов.
- Ограничить доступ по списку студентов/покупателей на backend. Не полагаться на скрытую кнопку, клиентский пароль или URL.
- Добавить rate limiting, лимиты стоимости, обработку ошибок и защиту от повторных запросов.
- Не передавать студенту системный промпт, ключи и закрытые внутренние документы.
- Учитывать согласие на микрофон, уведомление о записи/транскрипции и срок хранения данных.

## MVP по этапам
1. Каркас приложения и серверная проверка доступа.
2. Текстовый чат с retrieval по небольшой проверенной базе.
3. Голосовой ввод/ответ и прерывание воспроизведения.
4. Цитирование уроков и кнопка «полезно/неполезно».
5. История прогресса с настройками хранения.
6. Тесты безопасности, нагрузочные тесты и бюджетные лимиты.

## Критерии качества
- Не придумывает содержания уроков и характеристик моделей.
- Ссылается на материал курса, когда отвечает по нему.
- Голосовой стиль естественный, не превращается в длинный монолог.
- При слабом результате ученика диагностирует ролик и данные.
- Доступ закрыт для неавторизованных пользователей.
- API-ключ не появляется в browser bundle, git history или логах.
